# ScreenboxLite 性能基线与 v2 重构实测对比

## 1. 测试环境与样本

- **硬件环境**：Windows x64，24 逻辑线程 CPU，NVIDIA GeForce RTX 4070（`d3d11va` 硬件解码激活，渲染后端 `vo=gpu-next` / `d3d11`）
- **引擎版本**：`libmpv 2.6`（`mpv-dev-x86_64-20261111-git-bcde6b93cc`）
- **自动化测试入口**：`out\ScreenboxLite.exe --bench <视频路径> <输出报告>`（见 `src/Ui/MainWindow.Bench.cs`）
- **测试样本矩阵**（覆盖日常短视频与高码率长 GOP 极限场景）：
  1. `video_20260726_190123.mp4`：480×854，24fps，H.264，时长 133s（日常小视频代表）
  2. `1080p30_h264_gop250.mp4`：1920×1080，30fps，H.264，GOP=250 帧（8.3s 长关键帧间隔，115 MB）
  3. `1080p60_av1_gop10s.mp4`：1920×1080，60fps，AV1，GOP=600 帧（10s 超长关键帧间隔，90 MB）
  4. `4k60_hevc_gop10s.mp4`：3840×2160，60fps，HEVC，GOP=600 帧（10s 超长关键帧间隔，431 MB）

## 2. v1（MediaElement + FFmpeg 外挂补丁）vs v2（原生 libmpv）核心对比

| 指标 / 场景 | v1（MediaElement + FFmpeg） | v2（原生 libmpv 2.6） | 提升幅度与画质变化 |
| :--- | ---: | ---: | :--- |
| **源码规模与可维护性** | 单文件 `4,946` 行 + 硬编码路径 | 20 模块共 `3,992` 行（含自检+Bench+日志） | 职责清晰、零外部 FFmpeg 依赖 |
| **打开 1080p60 AV1 首帧可交互耗时** | `9,754.8 ms`（需整片转码 H.264） | **`9.5 ms`**（原生 `d3d11va` 硬解） | **快 1026×**，且彻底告别 CQ24 二次有损转码 |
| **按下 `~` 抓取当前原画帧（480p H.264）** | `107.0 ms`（`ffmpeg` MJPEG 管道） | **`20.3 ms`**（p50 `12.7 ms`） | **快 5.3×**，无损 `BGR0` 原画 vs 有损 MJPEG |
| **按下 `~` 抓取当前原画帧（1080p30 H.264）** | `224.0 ms`（`ffmpeg` MJPEG 管道） | **`19.0 ms`**（p50 `16.6 ms`） | **快 11.8×**，100% 原始像素无损 |
| **按下 `~` 抓取当前原画帧（1080p60 AV1）** | `375.7 ms`（且取自转码后缓存） | **`19.7 ms`**（p50 `17.2 ms`） | **快 19.1×**，真正 AV1 原片无损帧 |
| **按下 `~` 抓取当前原画帧（4K60 HEVC）** | `1,273.7 ms`（`ffmpeg` MJPEG 管道） | **`44.1 ms`**（p50 `41.0 ms`） | **快 28.9×**，3840×2160 无损秒进截图模式 |

## 3. v2 内部关键调优实验数据

### 实验 A：单帧前进模式对比（`Play` vs `Seek` vs `Turbo`）
`mpv` 默认 `frame-step`（`Play` 模式）会等待 `1/fps` 播放节拍（24fps 约 41ms，30fps 约 33ms）；`frame-step N seek` 则退回关键帧重解（长 GOP 下高达 95ms）。v2 默认采用 **`Turbo` 模式**（暂停逐帧期间临时置 `speed=100` + `frame-step N mute`，序列结束自动恢复原倍速）：

| 样本（单帧前进 `step+1` 连续 40 次） | `Play` avg / p50 | `Seek` avg / p50 | `Turbo`（默认）avg / p50 / p95 | 帧落点精度 |
| :--- | ---: | ---: | ---: | :---: |
| `480x854` 24fps H.264 | 41.5 / 42.1 ms | 12.7 / 13.2 ms | **5.6 / 0.4 / 11.7 ms** | 100 / 100 |
| `1080p30` H.264 GOP250 | 32.6 / 33.4 ms | 95.4 / 93.5 ms | **0.6 / 0.4 / 1.4 ms** | 99 / 100 |
| `1080p60` AV1 GOP600 | 16.0 / 17.3 ms | — | **0.4 / 0.3 / 0.7 ms** | 100 / 100 |
| `4K60` HEVC GOP600 | — | — | **0.4 / 0.4 / 0.5 ms** | 100 / 100 |

### 实验 B：`hr-seek-framedrop=yes` + 命令序号确定性导航器（`FrameNavigator`）
开启 `hr-seek-framedrop=yes` 并以 `mpv_command_async` 命令序号替代浮点 PTS 猜测后：
- `1080p30` GOP250 随机精确跳转（`seek.exact`）：平均耗时从 `133.9 ms` 降至 **`56.6 ms`**（p50 **`49.5 ms`**），连滚后退 8 帧（`wheel-8burst`）p50 从 `124.7 ms` 降至 **`49.7 ms`**；
- `4K60` HEVC GOP600 随机精确跳转（`seek.exact`）：平均耗时从 `391.0 ms` 降至 **`222.1 ms`**（p50 **`165.0 ms`**），连滚前进 8 帧（`wheel+8burst`）p50 仅 **`2.2 ms`**，帧落点精度 **100 / 100**。

## 4. v2 最终全量基准汇总（默认配置）

| 视频样本 | `file.open` | `step+1` (p50 / p95) | `wheel+8burst` (p50) | `step-1` (p50) | `wheel-8burst` (p50) | `seek.exact` (p50) | `grab` 原画截帧 (avg / p50) |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `480x854` 24fps H.264 | 10.5 ms* | **0.4** / 11.7 ms | **2.5 ms** | **7.6 ms** | **13.0 ms** | **5.3 ms** | **20.3 / 12.7 ms** |
| `1080p30` H.264 GOP250 | 11.2 ms | **0.4** / 1.4 ms | **11.0 ms** | **67.5 ms** | **49.7 ms** | **49.5 ms** | **19.0 / 16.6 ms** |
| `1080p60` AV1 GOP600 | 9.5 ms | **0.3** / 0.7 ms | **6.5 ms** | **351.9 ms** | **634.1 ms** | **241.5 ms** | **19.7 / 17.2 ms** |
| `4K60` HEVC GOP600 | 10.5 ms | **0.4** / 0.5 ms | **2.2 ms** | **83.2–1186 ms**† | **922.5 ms** | **165.0 ms** | **44.1 / 41.0 ms** |

> \* 冷启动首次含 D3D11 上下文预热约 `318 ms`，热态打开均约 `10 ms`。
> † 取决于当前位置距上一个 IDR 关键帧的帧数（GOP=600 帧即 10 秒才有一个关键帧的极限压测条件下，近关键帧端约 `83 ms`，跨 600 帧硬解端约 `1.18 s`；常规 2–4 秒 GOP 视频均在 `20–120 ms` 内）。
